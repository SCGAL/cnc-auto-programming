# 图像识别版数控自动编程工具（image_to_gcode）

> 输入一张零件轮廓图（PNG/JPG），自动输出车削精加工轮廓路径的 G 代码。
> 独立开发 · Python 3.11 / NumPy / Pillow

---

## 0. 先读这一段：范围与定位

**这是学习性工程项目，不是 Mastercam 的替代品。** 它只做一件事：

> **车削件上半部外轮廓 → 精加工轮廓路径 G 代码**

**明确不做**（写进代码、测试与报错信息，不在本版实现）：

| 不做 | 说明 |
|---|---|
| 粗车复合循环 G71/G70 | 真实生产必需，但属下一个层次 |
| 螺纹 / 切槽 / 钻孔 / 端面循环 | — |
| 内孔轮廓 / 多刀具 / 刀补 G41/G42 | — |
| 装配图 / 剖视图 / 多视图识别 | 只支持单张图、单一视图、一条连续外轮廓 |
| 尺寸公差 / 形位公差（GD&T）识别 | — |
| 剖面线 / 尺寸线 / 文字的**自动**剔除 | 要求干净输入（或后续用 ROI 框选） |
| 照片透视校正 | 后续版本 |
| 刀具干涉 / 过切仿真 | — |

CLI 强制要求显式给出 `--turning` 才会执行，就是对这条边界的确认动作。

## 1. 依赖

| 依赖 | 必需性 | 说明 |
|---|---|---|
| Python | 3.11+ | 开发环境 3.11.5 |
| numpy | **必需** | — |
| Pillow | **必需** | 图像 I/O 与基础操作 |
| ezdxf | **必需（间接）** | 复用的上游生成器 `../dxf_to_gcode_v2.py` 顶层 `import ezdxf` |
| opencv-python | **不需要** | 主实现完全不依赖；缺 cv2 时全流程可运行（有测试保证） |
| pytest | 测试用 | 已装到项目内 `_deps/`，不污染全局 |

主实现只用 **numpy + Pillow**；所有图像算法（Otsu、连通域、形态学、Moore 边界跟踪、
Zhang-Suen 细化、Douglas-Peucker、Kåsa 圆拟合、RANSAC、LM/Gauss-Newton 精修）**全部自研**。

## 2. 快速开始

```bash
# 最小用法（已知外径标定，最常用）
python cli.py part.png --ref-diameter 40 --turning -o out.nc

# 已知比例 + 输出中间过程图 + 自校验报告
python cli.py part.png --mm-per-px 0.1 --turning -o out.nc --viz out/viz --check --report out/report.txt

# 两特征点标定
python cli.py part.png --ref-points 120,300 640,300 --ref-mm 52 --turning -o out.nc

# 实心填充轮廓图（默认按线框笔画图处理）
python cli.py part.png --ink fill --ref-diameter 40 --turning -o out.nc
```

**三选一的标定参数必须给**，否则报错退出并打印提取到的轮廓像素包围盒供推算 ——
绝不默认假设 1 px = 1 mm。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 业务错误（缺标定 / 实体数为 0 / 轮廓不闭合 / 图像不可读）—— **明确报错，不静默输出垃圾** |
| 1 | 未预期异常（附完整 traceback） |

## 3. 精度现状（实测，非估计）

**结论先说：验收目标（DoD）目前尚未全数达成。** 详见《[精度验证报告](精度验证报告.md)》。

在合成真值测试集上的实测（10 px/mm、线宽 2 px、无倾斜无噪声、R5 圆角）：

| 指标 | 目标 | 实测 | 余量 |
|---|---|---|---|
| 直线端点误差 | ≤ 0.2 mm | **0.052 mm** | 3.9× |
| 圆弧圆心误差 | ≤ 0.2 mm | **0.069 mm** | 2.9× |
| 圆弧半径误差 | ≤ 0.2 mm | **0.047 mm** | 4.3× |
| 类型判别正确率 | ≥ 90% | **100%** | — |
| 圆弧识别率 | ≥ 90% | **100%** | — |
| 轮廓豪斯多夫距离 | ≤ 0.30 mm | **0.035 mm** | 8.5× |

> 上表数字取自 `tests/report/matrix_quick.json` 中用例 `px10_w2_s+0_n0_r5` 的一行，
> **不是手填的**：`test_readme_headline_numbers_match_reports` 会把它与本文件、
> 以及由 JSON 现算的值逐位比对，三者不一致即测试失败。
> 复现：`python -m tests.run_matrix --subset quick`。

**但把门槛条件铺开成全部 72 例（px_per_mm ≥ 10 且 noise = 0 的全组合）时，只有 56 例六项全过（77.8%）。**
把 6 项**分开**看独立达标率：

| 指标 | 独立达标率 | 最差实测 | 判读 |
|---|---|---|---|
| 圆弧识别率 | **100.0%** | 1.000 | 圆弧一次都没漏识别 |
| 圆心误差 | **100.0%** | 0.191 mm | 圆拟合链路已全域达标 |
| 半径误差 | **100.0%** | 0.093 mm | 同上 |
| 豪斯多夫距离 | **100.0%** | 0.272 mm | **轮廓形状全域达标** |
| 类型判别 | 87.5% | 0.889 | 与端点误差同源 |
| **端点误差** | **77.8%** | 1.142 mm | ← **剩余唯一瓶颈** |

**四项指标已在全部 72 例上达标**。形状对（豪斯多夫 100%）而端点有 22% 不达标，
说明剩余差距仍在"在哪里分段"，而不是"看不清"。

分维度看，**`skew = 0°` 已 18/18 全过**；缺口集中在 `fillet_r = 15`（58.3%）、
`line_width = 1`（62.5%）与带倾斜的组合。
根因、逐例分析与参数探针（`python -m tests.make_probe`）见
《[精度验证报告](精度验证报告.md)》第 4 节与第 9 节。

> 报告口径：**宁可给出一张有 22% 红格的实测矩阵，也不给一句没有依据的"精度达标"。**
> 这正是本项目立项时的出发点（上游 DXF 版的教训就是"跑通即交付"）。

## 4. 流水线

```
输入图像
  │
  ├─① preprocess.py   灰度 → Otsu 二值 → 去噪 → 形态学闭运算 → 小连通域剔除
  │
  ├─② centerline.py   倾斜角估计（投影直方图能量，三角核分箱）→ 旋转校正
  │
  ├─③ profile.py      Zhang-Suen 细化取**线条中线** → 图论最长路跟踪 → 亚像素精化
  │
  ├─④ vectorize.py    区域生长分段 → 直线/圆弧判别 → Kåsa 初值 → RANSAC → 几何精修 ★核心
  │
  ├─⑥ calibrate.py    像素 → 毫米（显式比例 / 已知外径 / 两特征点）
  │
  ├─⑤ snap.py         角度吸附 → 共线/共弧合并 → 端点求交 → 连续性检查
  │
  └─⑦ emit.py         转 v2 实体格式 → 调用 ../dxf_to_gcode_v2.py 的 generate()
       │
       └─ G 代码 + 精度报告 + 中间过程可视化
```

（⑤⑥ 顺序与立项文档不同，理由见下。）

**架构上最重要的一个决策**：G 代码生成**直接复用**已通过 9/9 契约校验的
`dxf_to_gcode_v2.py` 的 `generate()`，把风险隔离在"图像 → 几何"这一段。

## 5. 与《立项与可行性分析》的偏离（全部由实测驱动）

| # | 文档原方案 | 本实现 | 实测依据 |
|---|---|---|---|
| D1 | §6.1 示例真值 | **重建真值几何** | 文档示例 Z 从 −35 回退到 −30，Ø40 段与 Ø30 段在 Z 上重叠（物理不成立）；且"一条圆角连接两段外圆"在几何上不可能 —— 两条平行线不存在公共内切圆。详见 `tests/synth.py` 模块 docstring |
| D2 | "轮廓中线提取"列为 P1 | **提前进本版核心** | 线框图是笔画，直接描外边界会引入 +w/2 系统偏差：3 px 线宽 @10 px/mm = 0.15 mm，单这一项占掉预算 75% |
| D3 | §3.2④ DP 分段 → 逐段判别 | **改为区域生长 + 逐点模型选择**（DP 保留为 `--segment-method dp`） | DP 以 eps=1.5 px 会把 90° 圆弧切成 4 段弦，单段矢高仅 0.96 px，与骨架阶梯噪声同量级 → 实测 `arc_recall = 0` |
| D4 | ② 用 PCA 估计倾斜角 | **投影直方图能量最大化 + 三角核分箱** | PCA 受凹肩/倒角影响偏差 > 0.5°；而硬分箱的直方图能量曲线在零倾斜图上是一段平坦台阶（−0.100°~−0.025° 全等），搜索必然锁死在伪极值上，实测把 0° 图估成 −0.195° |
| D5 | ⑤吸附 在 ⑥标定 之前 | **先标定再吸附** | 吸附表格的容差全部以 mm 给出（共线 0.15 / 端点 0.2 / 闭合 0.5），单位未定就无法判断 |
| D6 | 去噪用 3×3 中值滤波 | **默认只去孤立点**（中值滤波保留为 `--denoise median`） | 二值图的 3×3 中值 = 多数表决，会**清零 1 px 笔画**（每个墨迹像素最多只有 3 个邻居，不到 9 的多数 5）。测试矩阵明确要求覆盖 `line_width = 1` |
| D7 | "闭合检查 = 首尾端点距离 > 0.5 mm 报警" | **改为"相邻实体连接间隙 > 0.5 mm 报错"** | 车削上半部外轮廓是**开路径**：首尾都落在轴线上、相距整个零件长度（本合成件 67~80 mm），按多边形闭合判会把合格零件一律判失败。文档语义实指 DXF 版的 `chain()` 断点检查 |
| D8 | 圆形截面拟合 | **圆弧与直线相切时改取切点而非交点** | 交点条件数在相切处是 sqrt 病态：\|R−d\| = 0.04 px 就让交点漂 2 px（0.2 mm）。实测圆角起点从 (−20,20) 算到 (−20.285,20) |
| D9 | — | **新增"曲率跳变切分"** | 肩面与两侧圆弧**相切**，残差判据对"多算一截肩面"几乎无感（12 px 肩面偏离 50 px 圆弧仅 0.14 px），必须靠转角跳变才能发现过渡 |
| D10 | — | **新增"贪心合并化简"** | 曲率切分为不漏过渡而偏灵敏，会把直线段切碎；实测 DoD 子集失败绝大多数是过度切分（提取 11~22 段 vs 真值 9 段） |
| D11 | 合成图 | **存抗锯齿灰度 PNG**（不是硬二值图） | 硬二值化丢掉覆盖率里的亚像素信息，会让数字骨架在曲笔画上产生 +2.4 px 的系统性半径偏差（R = 52.4 vs 真值 50）——那是测试集自身失真 |

## 6. 测试

```bash
python run_tests.py                      # 全部（快层）
python run_tests.py -m slow              # 含 DoD 门槛子集（72 例，约 5 分钟）
python run_tests.py tests/test_units.py -k rasterizer   # 只跑某组

python -m tests.run_matrix --subset quick   # 10 例冒烟
python -m tests.run_matrix --subset dod     # DoD 门槛子集
python -m tests.run_matrix --subset full    # 立项文档 §6.1 全矩阵（324 例）
python -m tests.run_matrix --subset resolution  # 精度-分辨率关系
python -m tests.make_probe                  # 参数探针（网格可配）
python -m tests.make_report                 # 重新生成《精度验证报告》
python -m tests.synth --profile             # 打印真值几何并自校验
```

### 测试分层

| 文件 | 内容 |
|---|---|
| `tests/synth.py` | 合成真值测试图生成器 + 真值几何 + **真值自校验** |
| `tests/metrics.py` | 6 项精度指标比对框架 |
| `tests/test_units.py` | **验证框架的自验证**（喂真值必须零误差、注入误差必须按比例响应）+ 几何核单元测试 |
| `tests/test_accuracy.py` | 6 项指标回归基线 + DoD 门槛 + 失败路径 |
| `tests/contract_checks.py` | G 代码契约校验（8 个断言项，对标 DXF 版 6 项检查 / 9 个断言的口径） |
| `tests/run_matrix.py` | 测试矩阵跑批 + 结果表 + 失败案例可视化 |
| `tests/make_probe.py` | 矢量化参数探针（可复现"某类失败是否只是调参问题"） |
| `tests/make_report.py` | 《精度验证报告》生成器（所有数字由 JSON 现算，不手填） |

**"先写验证，再写实现"不是口号**：`tests/synth.py` 与 `tests/metrics.py` 在任何算法代码之前完成，
且框架本身先自证（把真值喂回框架必须得到零误差；注入 0.35 mm 平移必须报出 0.35 mm）。
后续开发中，这套框架抓出的真几何错误、光栅化缺陷（只画端点不画线）、
0.5 px 映射偏差、ICP 增量/绝对量混淆等，都远早于人工调试。

## 7. 已知限制与后续版本

**本版已知限制**（均已在精度报告中量化）：

- `fillet_r = 15`（大半径圆角，R=15 mm）：通过率 58.3%
- `line_width = 1`（细笔画）：通过率 62.5%
- 带倾斜的组合（±1°/±2°）：61~83%（`skew = 0°` 已 100%）
- 噪声 2% 时端点误差约 0.12 mm（在预算内）；分段参数对噪声敏感，改动需一并回归
- `--ink fill`（实心填充图）兼容路径：端点误差约 1.0 mm，明显弱于线框模式
  （该路径靠 Moore 边界跟踪取区域边界，没有线框路径的逐点亚像素精化）
- 性能：轮廓点数上万后 `vectorize` 呈超线性（22k 点时单步 6.8 s）

**后续版本登记**（本版不做）：

| 版本 | 内容 |
|---|---|
| v2 | 粗车复合循环 G71/G70 输出 |
| v2 | ROI 交互框选（排除标注线/文字） |
| v2 | 多尺度曲率切分，解大半径圆角与细笔画的失败模式 |
| v3 | 照片透视校正（四点校正） |
| v3 | 自动剔除尺寸线/标注（连通域 + 直线长度分布先验） |
| v3 | 刀具轨迹仿真与干涉检查 |
| v4 | 铣削轮廓 / 内孔 / 多刀具 / 刀补 G41/G42 |
