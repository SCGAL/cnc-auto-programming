# image_to_gcode

**输入一张零件轮廓图，输出车削精加工轮廓路径的 G 代码。**

这是 [`数控自动编程工具集`](../README.md) 里的第二个项目。第一个项目读 DXF 矢量图纸，
这一个读位图——程序必须从像素里把几何**测量**出来。整体介绍与设计思路见
[`../项目介绍.md`](../项目介绍.md)，完整实测数据见 [`精度验证报告.md`](精度验证报告.md)。

---

## 这个工具做什么，不做什么

**做**：单张图片、单一视图、**一条连续的外轮廓**，车削件的上半部，输出精加工轮廓路径。
支持直线段、圆弧（圆角与倒角）、水平垂直斜线。

**不做**：

| 不做 | 说明 |
|---|---|
| 粗车复合循环 G71/G70 | 真实生产必需，但属于下一个层次 |
| 螺纹、切槽、钻孔、端面循环 | — |
| 内孔轮廓、多刀具、刀补 G41/G42 | — |
| 装配图、剖视图、多视图识别 | — |
| 尺寸公差与形位公差（GD&T）识别 | — |
| 剖面线、尺寸线、文字的自动剔除 | 要求输入干净，或用 ROI 框选 |
| 照片透视校正 | 后续版本 |
| 刀具干涉与过切仿真 | — |
| 与真机联调、适配具体控制器 | 见文末的已知限制 |

命令行**强制要求显式给出 `--turning`** 才会执行。这是对边界的
确认动作：要用的功能确实在范围内程序才动手。

## 安装

| 依赖 | 必需性 | 说明 |
|---|---|---|
| Python | 3.11+ | 开发环境 3.11.5 |
| numpy | **必需** | — |
| Pillow | **必需** | 图像读写与基础操作 |
| ezdxf | **必需（间接）** | 复用的上游生成器 `../dxf_to_gcode_v2.py` 顶部 `import ezdxf` |
| opencv-python | **不需要** | 主实现完全不依赖它，缺失时全流程照常运行（有测试保证） |
| pytest | 测试用 | 当前装在项目内 `_deps/`，不污染全局环境 |

二值化、连通域、形态学、Moore 边界跟踪、Zhang-Suen 细化、Kåsa 圆拟合、RANSAC、
Gauss-Newton 精修，这些图像算法全部是自己实现的，只用 numpy 和 Pillow。

## 用法

### 标定：三选一

程序需要知道"1 个像素等于多少毫米"。三种方式任选其一：

```bat
:: A. 已知外径（最常用）——取轮廓最大高度等于半径
python cli.py part.png --ref-diameter 40 --turning -o out.nc

:: B. 已知像素比例
python cli.py part.png --mm-per-px 0.1 --turning -o out.nc

:: C. 用两个已知距离的特征点
python cli.py part.png --ref-points 120,300 640,300 --ref-mm 52 --turning -o out.nc
```

**一个都不给时程序会直接报错退出**，并打印它提取到的轮廓像素包围盒供你推算比例：

```
错误: 缺少标定参数 —— 拒绝默认假设 1 px = 1 mm。请任选一种方式给出比例：
  --mm-per-px <毫米/像素>      已知比例
  --ref-diameter <毫米>        已知外径（推荐）：取轮廓最大高度 = 半径
  --ref-points x1,y1 x2,y2 --ref-mm <毫米>   已知两点距离
供推算的轮廓包围盒（像素）：Z 跨度 690.0 px, X 高度 199.4 px
  例：若该件外径为 Ø40，则 --ref-diameter 40；若已知长度 80 mm，则 --mm-per-px ≈ 0.115942
```

不默认假设 1 像素 = 1 毫米。一个尺寸整体差几倍的加工程序，比程序报错
危险得多。

### 常用选项

```bat
:: 输出中间过程图和自校验报告
python cli.py part.png --ref-diameter 40 --turning -o out.nc --viz out\viz --check --report out\report.txt

:: 实心填充的轮廓图（默认按线框笔画图处理）
python cli.py part.png --ink fill --ref-diameter 40 --turning -o out.nc

:: 图片本身有倾斜时（默认自动估计并校正）
python cli.py part.png --ref-diameter 40 --turning --skew 0 -o out.nc

:: 细笔画图（1 像素线宽）不要用中值滤波去噪，会整条清零
python cli.py part.png --ref-diameter 40 --turning --denoise isolated -o out.nc
```

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 业务错误——缺少标定参数、相邻实体间隙过大（轮廓不连续）、识别到的实体数为 0、轮廓方向回折、图像无法读取 |
| 1 | 未预期的异常，附完整调用栈 |

**程序不允许静默降级。** 上面这些情况一律明确报错，不会输出一个"看起来能用、
其实尺寸错了几倍"的程序。

## 精度现状

**验收目标尚未完全达到。** 目标是：在 10 px/mm 的图上，直线端点误差与圆弧圆心、
半径误差 ≤ 0.2 mm，圆弧识别率 ≥ 90%。把目标铺开成全部 72 种组合
（10 px/mm 以上、无噪声）时，**六项全过的有 56 种（77.8%），报错 0 例**。

在标准工况下（10 px/mm、线宽 2 px、无倾斜无噪声、R5 圆角），六项指标是：

| 指标 | 目标 | 实测 |
|---|---|---|
| 直线端点误差 | ≤ 0.2 mm | **0.052 mm** |
| 圆弧圆心误差 | ≤ 0.2 mm | **0.069 mm** |
| 圆弧半径误差 | ≤ 0.2 mm | **0.047 mm** |
| 类型判别正确率 | ≥ 90% | **100%** |
| 圆弧识别率 | ≥ 90% | **100%** |
| 轮廓豪斯多夫距离 | ≤ 0.30 mm | **0.035 mm** |

这六个数字不是手写的：测试 `test_readme_headline_numbers_match_reports` 会把它们与
`tests/report/matrix_quick.json` 逐位比对，对不上就直接测试失败。

分开看每一项在 72 例上的独立达标率：

| 指标 | 独立达标率 | 最差实测 |
|---|---|---|
| 圆弧识别率 | **100%** | 1.000 |
| 圆弧圆心误差 | **100%** | 0.191 mm |
| 圆弧半径误差 | **100%** | 0.093 mm |
| 轮廓豪斯多夫距离 | **100%** | 0.272 mm |
| 类型判别正确率 | 87.5% | 0.889 |
| **直线端点误差** | **77.8%** | **1.142 mm** |

四项指标已经在全部 72 例上达标。16 个失败例**全部**包含端点误差失败，
而端点误差一旦通过，其余五项必然通过，所以剩下的问题可以归结为一句：
**"在哪里把轮廓切开成直线段和圆弧段"**，而不是"看不清轮廓"。

## 流水线

```
输入图像
  │
  ├─① preprocess.py   灰度 → Otsu 二值 → 去噪 → 形态学闭运算 → 小连通域剔除
  │
  ├─② centerline.py   倾斜角估计（投影直方图能量）→ 旋转校正
  │
  ├─③ profile.py      Zhang-Suen 细化取中线 → 最长路跟踪 → 亚像素精化
  │
  ├─④ vectorize.py    区域生长分段 → 直线/圆弧判别 → 圆拟合 → 几何精修  ★核心
  │
  ├─⑤ calibrate.py    像素 → 毫米
  │
  ├─⑥ snap.py         角度吸附 → 共线共弧合并 → 端点求交 → 连续性检查
  │
  └─⑦ emit.py         转实体格式 → 调用 ../dxf_to_gcode_v2.py 的 generate()
```

⑤ 和 ⑥ 的顺序与最初的计划相反：**必须先标定再做几何吸附**。因为吸附的容差全部
以毫米给出（共线 0.15 mm、端点 0.2 mm、闭合 0.5 mm），单位没确定就无法判断。

一个关键点：线框图里的轮廓是**有宽度的笔画**，不是数学曲线。直接描外边界会引入
半个笔画宽度的系统性偏差——3 像素线宽在 10 px/mm 下是 0.15 mm，单这一项就吃掉
0.2 mm 预算的 75%。所以 ③ 这一步必须取笔画的中线。

G 代码生成这一段**直接复用**上游已经通过 9 项契约校验的 `generate()`，
不重写。这样图片版只需要对"图像 → 几何"这一段的精度负责。

### 每个环节为什么这么做

流水线里有好几处做法与教科书方案不同，因为实测把常规方案否决了：
倾斜角估计没用 PCA，分段没用 Douglas-Peucker，去噪没用中值滤波。
**完整的 11 处偏离及每处的实测依据，见 [`../项目介绍.md`](../项目介绍.md) 第 4 节。**

| `tests/test_units.py` | **验证框架的自验证**（把真值喂回去必须零误差、注入误差必须按比例响应）+ 几何核单元测试 |
| `tests/test_accuracy.py` | 6 项指标的回归基线 + 验收门槛 + 失败路径 |

系统性半径偏差。

## 已知限制

以下限制都已在《精度验证报告》里量化：

- **大半径圆角（R = 15 mm）通过率 58.3%**，是主要失效维度。原因是它和相邻肩面相切，
  在切点附近"多算一截肩面"对拟合残差几乎没有影响（半径 150 px 的圆弧吃掉 12 px 肩面，
  残差只涨 0.48 px，与骨架噪声同量级），基于残差的边界精修在该处失效。
- **1 像素细笔画通过率 62.5%**，骨架的量化自由度最小。
- **带倾斜的组合通过率 61~83%**（无倾斜时 18/18 全过）。
- **可用分辨率下限约 5 px/mm**，低于 4 px/mm 会崩坏。
- **端点误差在 10 px/mm 处进入平台**，继续提高分辨率不再改善（25 px/mm 仍是 0.041 mm）。
  这说明瓶颈是结构性的边界定位误差，不是采样密度不够。
- **`--ink fill`（实心填充图）模式明显弱于线框模式**：端点误差约 1.0 mm。该模式靠
  Moore 边界跟踪取区域边界，没有线框模式的逐点亚像素精化。这是已知取舍。
- **性能超线性**：区域生长的单步是 O(n²)。轮廓点上万后变慢，2.2 万点时 vectorize
  单步约 6.8 s。

### 上机前必须确认的事

1. **I/K 轴对应关系与圆弧旋向依赖控制器和刀架。** 这里按 Fanuc G18 标准实现，
   广数、新代、西门子的约定各有差异；**前置刀架与后置刀架的 G02/G03 需要互换**。
   必须在目标机床的手册上核对。
2. **输出的 .nc 是 UTF-8（无 BOM）编码、带中文注释。** 老式控制器或按 GBK 解析注释的
   系统可能出现乱码，建议先确认注释显示，或改用纯 ASCII 注释。
3. **本工具从未上过机床。** 全部验证是几何与代码规范层面的契约校验，
   没有真机或仿真器验证。
